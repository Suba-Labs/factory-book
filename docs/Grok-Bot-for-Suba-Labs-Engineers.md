## The short version

You already live in **Cursor for coding**. Grok Bot is different: Kyle talks to one assistant (**Sol, his EA**). Sol routes work to product managers and specialists, pulls Linear / Slack / GitHub / Gmail, and keeps a live book of work — so Kyle is not babysitting five chats and a pile of tabs.

## What Grok Bot is good for (how Kyle uses it)

- **One talk-to:** Kyle → Sol → Product Manager → people (agents + you). Decisions do not split across chats.
- **Run the house:** morning brief, intake when Linear or GitHub moves, live factory board at [sf.subalabs.ai](https://sf.subalabs.ai).
- **Route product work:** Honey = HomeHealthPulse + subalabs.ai. Atticus = Adlaw. Luisa = factory site (sf.subalabs.ai). Shared Kit (Eng), Edna (UX), Quinn (QA) get pulled by PMs.
- **Connectors, not tab hell:** Linear, Slack, GitHub, Gmail, Granola, and more — read tickets / PRs / mail / notes and act without copy-paste.
- **Ship discipline:** every change has a task id. No bot merges on HHP — **Christian still merges**. PHI stays out of Grok Bot chat.
- **Background routines:** Slack mentions, new Linear issues, PRs — filed and handed off while Kyle is on his phone.
- **Parallel threads:** HHP, Adlaw, site/leads, office — without dropping the coding lane.
- **Clear labels every turn:** already done / need you / running without you — so Kyle knows if he can walk away.

## What it is not

- **Not a second Cursor coding window.** Heavy repo work still goes through Cursor, cloud agents, and you.
- **Not a chart.** No patient names, DOB, MRNs, Hub / Careficient screens, or extract payloads in this chat. Ticket ids and bug rules only.

## What this means for you day to day

- Keep coding in **Cursor + Linear** the way you already do.

- **Christian** = HHP lead SE (merges).
